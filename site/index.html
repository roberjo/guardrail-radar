    • Mustel

      Non-AI static analysis, built for AI coding agents — Mustel is a local-first static analysis layer built specifically for AI coding agents like Cursor, Claude Code, and Windsurf. It runs Ruff, Bandit, and pip-audit under the hood, then compresses the output into a single sub-200-char agent_prompt field agents can act on directly - no wasted turns re-reading files or parsing raw linter noise. Dev Mode scans in under 30ms via mtime+size caching; Audit Mode runs deeper checks in CI. Auto-registers as an MCP server across major editors.

      Mustel wires Bandit (security) and pip-audit (dependency vulnerabilities) directly into the agent loop for Cursor, Claude Code, and Windsurf, compressing findings into a prompt an agent can act on instead of surfacing raw linter noise. The framing is worth noting on its own: it bills itself as "non-AI" static analysis feeding an AI agent — a deterministic, auditable check sitting in front of a coding agent's output, not another agent wrapper. A separate Audit Mode runs deeper checks in CI, distinct from the fast local dev-mode scan.

    • QuantDinger

      Self-hosted AI quant OS for research, backtests & trading — QuantDinger v5.0.1 is an open-source, self-hosted AI quant operating system. Research markets with multiple LLMs, turn ideas into auditable Python strategies, run deterministic backtests, then move safely from paper to live execution across crypto, stocks and forex. Connect Cursor, Claude Code or Codex through 25 scoped MCP tools. Your strategies, credentials and trading data stay on your infrastructure. Already trusted by 10,000+ GitHub stars.

      QuantDinger is a self-hosted, open-source quant trading OS that connects Cursor, Claude Code, or Codex through 25 scoped MCP tools — with strategies, credentials, and trading data explicitly kept on the user's own infrastructure rather than a vendor's cloud. For a fintech engineering team that can't send trading credentials or proprietary strategy logic to a third-party API, that's the adoption question answered by architecture rather than by a compliance add-on bolted onto a SaaS product. It also markets producing "auditable" Python strategies from LLM-assisted research — worth watching for how that claim gets substantiated as the project matures, since the excerpt doesn't say what makes a generated strategy auditable beyond being readable Python.

For engineers documenting infrastructure spanning cloud and industrial/OT environments, a tool treating OT/ICS as first-class rather than an afterthought is worth a look. The excerpt doesn't say which compliance frameworks those built-in checks actually cover, which is the first question to ask before relying on them.
