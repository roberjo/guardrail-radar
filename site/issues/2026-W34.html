  • Hands-Rust MCP/CLI that sees the Windows desktop and clicks real Chrome

    Notable1 min read

    Lets an agent click and type on a real desktop convincingly enough to dodge most automation detection.

    Hands is a Rust MCP/CLI that lets a coding-agent harness (Grok, Codex, Claude Code, OpenCode, etc.) drive a real Chrome profile via actual OS-level input — not Playwright, Puppeteer, or a remote debugging port — specifically so sites that key off CDP/automation flags mostly don't detect it as automated. Genuinely useful for legitimate testing, and also a direct description of how to make agent-driven browser activity indistinguishable from a human's to any system trying to tell the difference. Worth knowing this class of tool exists before assuming your bot-detection or session-monitoring controls would catch an unsanctioned agent using one.

    Read the source excerpt
    I built Hands because I wanted a coding agent to use this Windows PC and a real Chrome profile the way I do: look at the screen, move the real mouse, type, click , without turning Chrome into an automation browser. It is a Rust MCP/CLI. A harness (Grok, Codex, Claude Code, OpenCode, etc.) calls tools like observe, click, type, scroll. Observe is a screenshot path plus a small element list (UIA + optional Chrome DOM ids). Click is OS SendInput on a Bézier path, not a Chrome DevTools click. There is no Playwright, no Puppeteer, no remote debugging port. Daily Chrome is launched with no extra flags, or attached if it’s already open.   • Anthropic appears to be A/B testing reduced effort levels in Claude Code

    Breaking1 min read

    Claude Code may quietly be running on a lower effort setting for you right now, with no client update or announcement.

    An HN commenter reports Anthropic silently enrolling some Claude Code sessions (Fable 5, version 2.1.236+) into a server-side experiment that shrinks the effort scale — no client update required to trigger it, with older versions and Opus 5 sessions left alone. The report itself frames this as probably an A/B test, not a confirmed universal rollout, and there's no official Anthropic statement cited here. Still worth flagging: a coding agent's reasoning behavior changing server-side and invisibly, mid-deployment, is exactly the kind of vendor-controlled variable that's hard to account for in a change-managed environment.

  • Coding Agents killed my identity. How do you feel?

    Field Notes1 min read

    One senior engineer's unfiltered account of what full agent delegation actually feels like.

    A full-time software engineer writes on HN that they realized they hadn't personally written code in over a month — not from moving into management, but because agents had gradually taken over first the boilerplate, then the planning and architecture, leaving them mostly supplying context and infrastructure details. Framed as "winning with a chess engine": still shipping, but with the part of the job they valued removed. Worth surfacing for any engineering lead rolling out agent adoption — retention and job-satisfaction risk is a real cost that a pure productivity metric won't show.

    Read the source excerpt
    Programming is like a game of chess for me: winning (i.e. delivering a product) is important, but only if I played this game myself. I don't enjoy winning if my opponent disconnected. I don't enjoy beating people who don't know how to move pieces. I don't enjoy winning with an engine, and coding agents are basically "winning with a chess engine". I started to use AI for coding a long time ago, when copilot was first introduced. At first, I was happy: "wow, this can write boring boilerplate and unit tests". Time went by, agents got better, time spent writing code myself went down. Half a year ago I suddenly realized I hadn't written any code for over a month, and I am a full-time software dev without any managing work.   • FetchSandbox MCP

    New Product1 min read

    Proves an AI agent's fix actually held, not just that it passed CI.

    FetchSandbox MCP targets a specific failure mode this audience will recognize: an agent's fix passes CI while the underlying data or integration behavior is still wrong. It reproduces the real failure against one of 70+ API sandboxes and re-verifies the fix actually held, rather than trusting a green test run — positioned explicitly as "a receipt, not a vibe." For a team that has to show its work on why an AI-assisted change was safe to ship, that's the right instinct, though the excerpt doesn't say what the receipt actually contains or where it's stored for later audit.

  • Pawvis

    New Product1 min read

    A free, fully on-device Mac gesture-control tool that can also hand off computer-use tasks to Codex or Claude Code.

    PawVis turns a Mac's webcam into a hand-tracked mouse and gesture controller, running entirely on-device and shipping free and open source — the same "nothing leaves the machine" architecture this list keeps flagging as the practical answer to data-governance objections about AI tooling. It's mostly a hands-free input/accessibility tool, but one of its listed use cases is handing computer-use tasks directly to Codex or Claude Code, which adds another local automation surface worth knowing about alongside this week's browser-driving Hands entry for anyone auditing what can now operate a workstation without a human directly at the keyboard.

    Read the source excerpt
    Control your Mac via camera & train gestures, local & FOSS — PawVis turns your Mac’s webcam into a hand-tracked mouse, no extra hardware required. Raise your hand and the cursor follows, dip a finger to click, and fold two fingers to scroll. Map gestures to custom actions like window management or any app/command from a series of common gestures or train your own. Everything runs 100% on-device, and PawVis is free and open source. Enable optional voice control for hands-free commands, or pass computer-use tasks to Codex or Claude Code.

  • Slack Code

For a regulated team, "who approved this AI-generated change and where's the record" is exactly the kind of question this starts to answer, though the excerpt doesn't say whether that approval trail is retained anywhere durable, or just lives in Slack's normal message history.
